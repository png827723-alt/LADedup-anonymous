# Python Case1 + Cluster Runner

This folder contains a standalone runner:

- `run_case1_cluster.py`
- `Greedy_benefit_size.py`
- `GraphCommunity_benefit_size.py`

It runs:

- file clustering (`clusterFiles`-style flow)
- Case1 selection (`Case1_selectFile`-style flow)

Input is `mean_go_v1` JSON (generated by `../fileinfo_builder/build_fileInfo_from_dataset.go`).

## 1) Minimal Files To Copy

If you want to run in another directory/machine, copy only:

- `run_case1_cluster.py`
- your dataset JSON (for example `fileInfo-src.json`)

No MATLAB files are required for this Python runner.

## Benefit/Size Greedy Baseline

`Greedy_benefit_size.py` selects original files directly without clustering. In
each round it recomputes a completion-aware dedup marginal score:

```text
score_i = sum_{j completed by adding i} heat_j * max(0, T_cloud_j - T_edge_j)
          / delta_unique_size_i
```

where `delta_unique_size_i` is the number of bytes from file `i` that are not
already cached at the edge. A file contributes to the numerator only when all
of its chunks become cached at the edge, matching the restore-fileinfo-batch
cloud fallback rule.

Example:

```bash
python3 Greedy_benefit_size.py \
  --input-json ../data/input/8KB/fileInfo-zipf-s0.7.json \
  --env-file ../../compose.paths.env \
  --output-json ../data/output/case1_greedy_benefit_size.json \
  --capacity-ratio 0.2 \
  --server-num 10 \
  --no-progress
```

## Graph Community + Benefit/Size Greedy

`GraphCommunity_benefit_size.py` first builds a sparse file graph from shared
chunks, extracts fast union-find communities, and then runs the same
completion-aware greedy with a small community benefit boost:

```text
score_i = completion-aware-greedy-score_i * (1 + community_bonus_i)
```

The graph builder is designed for many files: low-degree chunks add sparse
union edges, while high-degree chunks union through a few high-benefit hubs to
avoid pair explosion.

Example:

```bash
python3 GraphCommunity_benefit_size.py \
  --input-json ../data/input/8KB/fileInfo-zipf-s0.7.json \
  --env-file ../../compose.paths.env \
  --output-json ../data/output/case1_graph_community_benefit_size.json \
  --capacity-ratio 0.2 \
  --server-num 10 \
--no-progress
```

Useful scalability knobs:

```text
--pair-degree-limit 16
--high-degree-hubs 4
--high-degree-neighbors 2
--community-bonus 0.25
```

## Dedup-Only Baseline

`Dedup_only.py` ignores heat and restore-time modeling. It selects original
files by deduplication amplification only:

```text
score_i = sum_{j completed by adding i} raw_size_j / delta_unique_size_i
```

This means a candidate is preferred when storing its missing unique chunks makes
more logical file bytes fully restorable from the edge. Like the other baselines,
capacity is charged only by newly introduced unique chunk bytes.

Example:

```bash
python3 Dedup_only.py \
  --input-json ../data/input/8KB/fileInfo-zipf-s0.7.json \
  --output-json ../data/output/case1_dedup_only.json \
  --capacity-ratio 0.2 \
  --server-num 10 \
  --no-progress
```

## 4) Main Parameters

- `--input-json`: input metadata JSON path (`mean_go_v1`)
- `--output-json`: output result JSON path
- `--k`: number of minimum-distance pairs considered per clustering round
- `--alpha`: max clustering rounds
- `--capacity-ratio`: total storage ratio for Case1
- `--server-num`: number of edge servers for chunk placement
- `--workers`: process count for distance computation
- `--progress` / `--no-progress`: enable/disable progress bars
- `--max-files`: debug option, limit number of input files

## 5) Notes

- Clustering flow is aligned with MATLAB-style logic:
  - build distance table once
  - incremental updates after each merge round
  - k-pair selection follows `minkFilePairFunc`-style strict `<` behavior
- In restricted environments where multiprocessing is not allowed, script
  automatically falls back to single process.
- Output JSON is compact and contains:
  - `input_json`, `format`, `params`, `summary`
  - `hash2edge_node_id` (chunk hash -> edge node id)
